## 角色与原则

你的目标不是“想办法把它跑起来”，而是**严格按照仓库当前版本完成可回退的首次验证**。

必须遵守：

- 以仓库当前文件为唯一事实来源，不使用你记忆中的旧版本参数、旧聊天记录或其他设备的值。
- 不猜测网卡、网关、IPv6、ifIndex、DHCPv6、MTU、节点地址或客户端状态。
- 任何与文档预期不一致的结果都要先停止、解释，再决定是否继续。
- 首次验证中不要为了绕过检查而增加 `-Force`、手动改状态文件、手动改 ProgramData 中的脚本或跳过安全门。
- 一次只完成一个阶段；每个阶段结束后先让我确认输出。
- 修改系统前必须先说明：修改对象、目的、预期结果、验证方式、恢复方式。
- 如果某一步失败，不要连续试多个“修复命令”；先保留输出和现场。
- 不把流量统计、公开 IPv6 测试网站或单次速度结果当作系统配置成功的唯一依据。

## 首次验证流程

严格按以下阶段推进，不要合并阶段：

### 阶段 A：只读环境检查

先执行 `docs/01-环境检查.md` 中的只读检查。

确认至少包括：

- 当前确实连接目标校园有线网络；
- IPv6 正常启用；
- 存在物理 IPv6 默认路由；
- 当前接口地址符合仓库文档描述；
- 没有同时运行其他 TUN 客户端；
- CrushCloud 可正常启动。

如果结果不符合预期，停止，不进入安装。

### 阶段 B：配置与覆写核对

检查 CrushCloud 当前配置是否符合 `docs/02-客户端配置.md` 和 `docs/03-IPv6覆写.md`。

不要要求我发送订阅 URL、节点 password、Token、Cookie 或账号密码。

只确认必要的非敏感状态，例如：

- 覆写是否已应用；
- UI 中节点范围是否符合预期；
- TUN / mixed-port 等设置是否与文档一致。

### 阶段 C：安装前留档

运行：

~~~text
scripts/Run-Diagnostics.cmd
~~~

让我保存生成的 diagnostics 文件。

如果诊断结果出现明显异常，停止，不安装。

### 阶段 D：安装

只使用：

~~~text
scripts/Run-Install.cmd
~~~

不要自己拼接 `Install.ps1 -Force`。

安装器如果拒绝继续，例如检测到旧任务、已有安装目录、校园特征不成立，不要删除或绕过这些保护。先解释原因并停止。

只有当安装器显示的：

- 物理接口；
- ifIndex；
- IPv6 网关；
- 当前 IPv6；
- 自动派生的运行时 /64；

都与当前实际环境一致时，才让我输入 `YES`。

### 阶段 E：第一次 Check

安装完成后等待约 10 秒，运行：

~~~text
scripts/Run-Check.cmd
~~~

解释所有 PASS / WARN / FAIL。

规则：

- 有 FAIL：停止。
- WARN：说明是否属于预期情况，再决定是否继续。
- 不允许为了消除 WARN 而自动修改网络。
- 不要仅依据公开 IPv6 网站显示的出口协议判断 Core 到节点的外层链路。

### 阶段 F：按验证清单逐项测试

后续严格按照：

~~~text
docs/10-首次独立环境验证清单.md
~~~

依次做 Core 重启、离开目标网络、热点 MTU、卸载回退等测试。

每完成一项再进入下一项。

## 明确禁止

必须遵守 `ai/AI-禁止事项.md`。

尤其不要：

- 禁用 IPv6；
- 执行 Windows 网络重置、Winsock reset 或 TCP/IP reset；
- 删除默认路由；
- 批量删除虚拟网卡；
- 修改物理以太网 MTU；
- 手工写死其他设备的 ifIndex、DHCPv6 地址或网关；
- 未经验证修改 DNS、接口跃点、静态 IPv6、ICS/NAT 或防火墙；
- 同时开启两个 TUN 客户端；
- 删除 `state.json` 来“重新开始”；
- 修改 `C:\ProgramData\CampusIPv6Lab` 中的文件来绕过安装器；
- 看到错误后自行扩大修改范围。
