# AI 完整总控提示词

> 用法：把本页从“开始”到“结束”完整复制给一个具备网页/GitHub读取能力的 AI。  
> 本提示词要求 AI 自行读取公开仓库、先审计当前 main 分支，再决定是否进入本机实验。

---

## 开始

你现在负责协助我审计、部署、验证并在必要时排查一个 Windows 校园网络 IPv6 配置实验。

公开 GitHub 仓库：

https://github.com/Niceskys/-ipv6-

默认分支：

main

你的任务不是照着 README 机械执行，也不是想办法“无论如何让它跑起来”。

你的任务是：

1. **先自行读取并审计仓库当前 main 分支。**
2. **以当前仓库实际源码为准，交叉核对 README、docs、ai、scripts、overrides 和 GitHub Actions。**
3. **确认没有明显高风险问题、版本错位或文档/代码冲突后，再进入本机只读环境检查。**
4. **在我的明确确认下，逐阶段完成首次实验。**
5. **全过程保证可验证、可恢复、不过度修改系统。**
6. **出现异常时自动切换到保守排障流程，而不是扩大修改范围。**
7. **完成后给出最终验证结论，并明确哪些内容已验证、哪些仍未验证。**

# 二、先做独立仓库审计，不要先碰本机网络

读取完成后，先进行一次独立审计。

不要默认：

- README 一定正确；
- 文档一定与源码同步；
- CHANGELOG 一定准确；
- GitHub Actions 通过就代表实机一定安全；
- 项目作者之前的结论一定正确。

你必须至少审计以下内容。

## A. 版本一致性

检查：

- `VERSION`
- README 中版本
- docs 中版本
- scripts 文档中版本
- CHANGELOG 最新版本

如果版本互相不一致，标记为 HOLD，不进入安装。

## B. PowerShell 安全性

检查源码是否存在或变相存在：

- 禁用 IPv6；
- 修改系统级 IPv6 禁用注册表项；
- Windows 网络重置；
- Winsock reset；
- TCP/IP reset；
- 删除 IPv4 默认路由；
- 删除 IPv6 默认路由；
- 批量删除/重建网卡；
- 修改物理以太网 MTU；
- 未记录原值就修改 SkipAsSource；
- 未记录原值就修改热点 MTU；
- 无所有权记录地新增/删除路由；
- 删除状态文件后继续运行；
- 恢复失败却清空回退信息；
- 在非目标网络继续修改；
- 把某一台参考机的 ifIndex、DHCPv6 主机地址、接口 GUID 写死；
- 普通用户可以修改 SYSTEM 计划任务实际执行的脚本/配置；
- 使用 `-Force` 作为正常安装路径；
- 计划任务或 Helper 可能重复安装、互相冲突；
- 安装失败后留下不可恢复的半安装状态。

## C. 网络识别安全门

检查安装器和 Helper 是否：

- 只在物理网络环境满足条件时工作；
- 能识别 IPv6 默认路由；
- 能确认目标 IPv6 地址范围；
- 安装时记录精确运行环境，而不是永久信任一个过宽范围；
- 离开目标网络后停止修改并恢复自己管理的状态；
- 不会在普通 Wi-Fi、手机热点或其他网络上继续套用校园配置。

## D. IPv6 源地址策略

检查：

- Router Advertisement 地址与 DHCPv6 地址处理是否与项目当前实验基线一致；
- 是否只改目标接口；
- 修改前是否记录原值；
- 恢复时是否只恢复本项目改过的地址；
- DHCPv6 主机地址是否动态识别而非硬编码。

## E. 节点 /128 路由

检查：

- 只观察 CrushCloud 对应核心；
- FlClashCore 的识别是否有路径限定，避免误识别其他 FlClash；
- 只处理合理的节点 IPv6 地址范围；
- 最好只基于已建立连接；
- 添加 /128 前是否保留所有权信息；
- 不会把任意公网 IPv6 都加入物理绕行；
- 恢复时不会删除不属于本项目的路由。

## F. 热点 MTU

检查：

- 只改 Windows 移动热点接口；
- 不改物理以太网 MTU；
- 修改前保存原始 MTU；
- Core 退出或离开目标环境时可以恢复；
- 热点接口被 Windows 重新创建时不会覆盖旧回退信息。

## G. 卸载/恢复

检查：

- 卸载前先停止后台任务；
- 恢复失败时是否保留状态文件；
- 是否只恢复本项目自己的修改；
- 不做全局网络重置；
- 不删除 CrushCloud 或其他代理软件；
- 不清理非本项目路由。

## H. 诊断与隐私

检查诊断脚本是否避免主动读取或输出：

- 订阅 URL；
- 节点 password；
- Token；
- Cookie；
- 浏览器数据；
- 账号密码。

同时检查是否收集了明显无必要的个人标识。

## I. JavaScript 覆写

检查 `overrides/campus-ipv6.js` 是否：

- 只保留预期的香港 V6 节点；
- 自动选择与故障转移不会混入 V4 或其他地区；
- 找不到符合条件的节点时 Fail-Closed；
- 不会静默回退到 V4；
- 健康检查逻辑合理；
- 保留必要的原有 TUN exclude；
- 不会因为节点命名轻微变化而误把 V4 当 V6。

## J. CI / 自动测试

如果仓库有 GitHub Actions：

检查最新运行是否成功，并确认至少覆盖：

- Windows PowerShell 5.1 语法；
- PowerShell 7 语法；
- IPv6 CIDR / 前缀逻辑；
- 覆写脚本语法；
- 覆写 Fail-Closed 行为；
- 明显危险命令静态扫描。

注意：

**CI 成功只能说明自动测试覆盖范围内通过，不能代替实机验证。**

# 四、本机实验总原则

开始本机实验后，必须遵守：

- 一次只完成一个阶段。
- 每个阶段完成后，先解释结果并让我确认，再进入下一阶段。
- 不一次给几十条命令。
- 每条额外命令必须说明是“只读”还是“会修改系统”。
- 优先使用仓库已有脚本，不自行重新发明另一套安装方案。
- 不猜测任何本机网络参数。
- 不使用其他设备上的 ifIndex、DHCPv6 地址、网关、GUID。
- 不根据一次测速或体感直接永久修改配置。
- 有 FAIL 必须停。
- WARN 必须解释，不能为了消掉 WARN 就乱改系统。
- 系统级修改必须可恢复。
- 不把公开 IPv6 检测网页的结果当成 Core 到节点外层链路的唯一依据。
- 不把任何流量统计现象当作长期规则或保证。

# 六、绝对禁止

除非仓库未来经过明确审计并正式改变设计，否则不要执行：

- 禁用 IPv6；
- 修改系统 IPv6 禁用注册表；
- Windows 网络重置；
- `netsh winsock reset`；
- `netsh int ip reset`；
- 删除 IPv4 默认路由；
- 删除 IPv6 默认路由；
- 批量删除、禁用或重建虚拟网卡；
- 修改物理以太网 MTU；
- 手动写静态 IPv6 来替代自动识别；
- 随意修改 DNS；
- 随意修改接口跃点；
- 随意修改 ICS/NAT；
- 随意打开 IP Forwarding；
- 随意修改防火墙；
- 在同一设备同时运行多个接管系统流量的 TUN 客户端；
- 用 `-Force` 绕过首次实验的安全检查；
- 删除 `state.json` 来“重新开始”；
- 修改 `C:\ProgramData\CampusIPv6Lab` 中的文件来绕过安全门；
- 恢复失败后直接覆盖重装；
- 因为一条命令失败就连续尝试多个破坏性命令。

原则：

> 不确定时停止，不猜。  
> 恢复不了时保留现场，不清空。  
> 文档和源码冲突时，以源码行为为准并停止实验，先解释冲突。

# 十四、阶段 7：离开目标网络测试

这是安全性验证，不要跳过。

按文档：

1. 先退出 CrushCloud；
2. 断开目标校园有线网络；
3. 等待超过 Helper 的恢复阈值；
4. 如需要，可以切换普通 Wi-Fi / 手机热点；
5. 运行 Check 或 Diagnostics。

必须验证：

- Campus Safety Gate 不再成立；
- Helper 不修改新网络的 IPv6 地址策略；
- 本项目创建的节点 /128 路由被清理；
- 本项目管理的热点 MTU恢复；
- 默认路由没有被删除；
- IPv6 没有被禁用；
- 普通网络仍可正常使用。

只要发现 Helper 在新网络继续套用校园配置：

判定失败，停止后续测试。
