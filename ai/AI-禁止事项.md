# AI 禁止事项

如果你是协助用户执行本仓库的 AI，必须遵守本页。

本仓库的目标是可验证、可恢复地完成网络配置实验，不是为了“让结果看起来成功”而扩大系统修改范围。

## 严禁自行执行

- 禁用 IPv6 或修改系统级 IPv6 禁用注册表项。
- 执行 Windows“网络重置”。
- 执行 `netsh winsock reset`、`netsh int ip reset` 等整体重置。
- 删除 IPv4 / IPv6 默认路由。
- 批量删除、禁用或重建虚拟网卡。
- 修改物理以太网 MTU。
- 把其他设备的 ifIndex、接口 GUID、DHCPv6 地址、IPv6 网关直接写入当前设备。
- 手动配置静态 IPv6 来代替自动检测。
- 未验证就修改 DNS、默认网关、接口跃点、ICS/NAT、IP 转发或防火墙规则。
- 在同一设备上同时开启两个会接管系统流量的 TUN 客户端。
- 使用 `-Force` 绕过首次验证中的安装器安全检查。
- 直接修改 `C:\ProgramData\CampusIPv6Lab` 中的脚本、配置或状态文件来绕过保护。
- 删除 `state.json`、日志或安装目录来掩盖恢复失败。
- 在恢复失败后继续覆盖安装。
- 为了让步骤“成功”而扩大修改范围。
- 在聊天、日志、截图、诊断报告或仓库中输出订阅 URL、节点 password、Token、Cookie、账号密码。

## 执行纪律

1. 以仓库当前版本为准，不使用旧聊天或旧版本中的硬编码参数。
2. 一次只完成一个阶段。
3. 修改前说明修改对象、目的、预期结果、验证方法和恢复方式。
4. 只读检查优先于修改。
5. 命令失败时先保留并解释输出，不连续尝试破坏性命令。
6. 发现实际环境与文档不一致时停止。
7. 不确定某个值时重新检测，不猜。
8. 系统修改必须可逆。
9. 只恢复本项目自己记录并修改过的对象。
10. Helper 的状态文件无法读取或恢复不完整时，优先保留现场，不删除记录。
11. WARN 需要解释，FAIL 必须停止当前阶段。
12. 不把单个测速、延迟、公开 IPv6 测试页面或流量统计结果当作配置正确与否的唯一依据。

## 允许的处理方式

可以：

- 执行文档明确列出的只读检查；
- 运行仓库提供的 Check / Diagnostics；
- 按仓库安装器显示的实际环境进行人工确认；
- 在用户明确确认后执行文档已有、可恢复的修改；
- 根据 diagnostics 和日志逐层定位问题；
- 在无法确认安全性时停止并要求人工复核。

原则是：

> 不确定时停止，不猜；恢复不了时保留现场，不清空。
