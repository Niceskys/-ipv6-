# 10 首次独立环境验证清单

本页用于第一次在独立设备上验证 v0.2.1 通用脚本。

目标不是证明所有电脑都能用，而是确认脚本没有依赖参考机的历史状态。

## 0. 前置要求

- 当前连接校园有线网络。
- 校园网认证正常。
- Windows IPv6 正常。
- CrushCloud 已能正常打开并使用自己的账号/订阅。
- 已应用 `overrides/campus-ipv6.js`。
- 不运行其他 TUN 客户端。
- 不做大流量测试。

## 1. 安装前留档

先运行：

~~~text
scripts/Run-Diagnostics.cmd
~~~

保留生成的 diagnostics 文件。

## 2. 安装

运行：

~~~text
scripts/Run-Install.cmd
~~~

安装器必须显示：

- 检测到的物理接口；
- 当前 ifIndex；
- IPv6 网关；
- 匹配校园前缀的 IPv6 地址。

如果这些信息明显不是当前校园有线网，输入内容以外的任意值取消，不要继续。

## 3. 第一次 Check

安装后等待 10 秒，运行：

~~~text
scripts/Run-Check.cmd
~~~

重点检查：

- 计划任务存在；
- Campus Safety Gate 为 PASS；
- CrushCloud Core 能被识别；
- IPv6 源地址策略没有 FAIL；
- 如果核心已有节点连接，应能看到符合节点前缀的远端；
- 没有 FAIL。

WARN 不一定代表故障，例如热点没开、核心暂时没建立节点连接。

## 4. Core 重启测试

1. 关闭 CrushCloud。
2. 等待约 10 秒。
3. 再打开 CrushCloud。
4. 等待 10~20 秒。
5. 再运行 Check。

目标：

- Helper 不崩溃；
- 新 Core PID 可以被重新识别；
- 节点连接恢复后可重新建立 /128 路由。

## 5. 离开校园网络测试

这是通用版最重要的安全测试之一。

1. 先关闭 CrushCloud。
2. 断开校园有线网络。
3. 等待至少 20 秒。
4. 可以切换到普通 Wi-Fi/手机热点。
5. 运行 Check 或 Diagnostics。

预期：

- Campus Safety Gate 不再 PASS；
- Helper 不应该修改新网络的 IPv6 源地址；
- 本项目创建的节点 /128 路由应被清理；
- 本项目管理的热点 MTU 应恢复原值。

如果发现离开校园后仍持续修改其他网络，立即执行卸载并保存 diagnostics。

## 6. Windows 移动热点测试

重新回到校园有线网络并启动 CrushCloud。

1. 开 Windows 移动热点。
2. 等待 10 秒。
3. 运行 Check。

预期：

- 能检测到 192.168.137.1；
- 热点接口 MTU 为 1400；
- 物理以太网 MTU没有被改变。

关闭 CrushCloud 后等待约 10 秒，再检查热点 MTU，应恢复安装前记录值。

## 7. 卸载回退测试

首次独立机器验证建议最后完整测试一次卸载：

~~~text
scripts/Run-Uninstall.cmd
~~~

卸载后检查：

- `CampusIPv6LabHelper` 计划任务不存在；
- 项目 /128 路由不存在；
- 项目记录的 SkipAsSource 已恢复；
- 热点 MTU 已恢复；
- Windows IPv6 仍然启用；
- 物理默认路由仍然存在；
- CrushCloud 本体没有被删除。

## 8. 提交验证结果

如果需要反馈给维护者或 AI，请提供：

- 安装前 diagnostics；
- 第一次 Check 输出；
- Core 重启后的 Check；
- 离开校园网络后的 Check/diagnostics；
- 卸载后的 diagnostics。

不要提供：

- 订阅 URL；
- 节点 password；
- Token；
- Cookie；
- 账号密码。

## 通过标准

只有完成以上测试且没有出现系统网络副作用，才把 v0.2.1 从“单机静态审计通过”提升为“独立环境实机验证通过”。
