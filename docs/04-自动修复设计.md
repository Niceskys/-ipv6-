参考环境中的 AutoFix 已经过较长时间验证。仓库 v0.2.1 提供第一版通用化实现，目前仍按“测试版”管理。


## 安全门

安装阶段不会把“当前任意网络”直接记成目标网络。

默认要求同时满足：

- 物理网卡处于 Up；
- 该物理网卡存在 IPv6 默认路由；
- 默认网关为 link-local IPv6；
- 该接口存在属于 `2001:da8:a012::/48` 的 /64 IPv6 地址。

安装确认后，会从当前地址自动派生并记录当次环境的精确 /64。后台 Helper 只在这个已记录 /64 再次出现、且物理 IPv6 默认路由仍成立时进入工作状态。

因此：

~~~text
安装识别范围：较宽的已知校园地址范围
运行时安全门：安装时记录的精确 /64
~~~

不能确认时直接 Fail-Closed，不修改新网络。

如果以后网络规划发生变化，应重新检查并重新安装，而不是自动学习新的地址范围。

## 自动发现

运行时动态发现：

- 物理 IPv6 默认路由；
- 实际物理网卡 ifIndex / GUID；
- 当前 IPv6 网关；
- 当前 DHCPv6 / Router Advertisement 地址；
- CrushCloud 核心进程；
- 符合节点 IPv6 范围的已建立 TCP 连接；
- Windows 移动热点接口。

不会写死某台设备的 ifIndex 或 DHCPv6 主机地址。

## IPv6 源地址策略

当前实验基线：

~~~text
RouterAdvertisement -> SkipAsSource=True
DHCPv6              -> SkipAsSource=False
~~~

Helper 在修改前先记录原值。离开目标环境或卸载时，只恢复由本项目记录过的地址。

## 节点 /128 绕行

Helper 只观察 CrushCloud 核心进程，并且只处理配置中的：

~~~text
NodeIPv6Prefix = 2406:da18::/32
~~~

发现符合范围且状态为 Established 的核心连接后，为对应远端 IPv6 添加 `/128` ActiveStore 物理路由。

路由所有权采用“先记录、后修改”方式：即使修改过程中意外中断，状态文件仍保留回退依据。

不会把所有 IPv6 连接都当作代理节点。

## 热点 MTU

仅当：

~~~text
运行时安全门成立
AND CrushCloud Core 正在运行
AND 192.168.137.1 热点存在
~~~

才管理热点接口 MTU。

默认目标值：

~~~text
1400
~~~

修改前记录接口 GUID、接口索引和原始 MTU。Core 退出、离开目标环境或卸载时恢复原值。

如果 Windows 重新创建热点接口，Helper 会先尝试恢复之前记录的接口；旧状态无法安全恢复时，不接管新的热点接口。

不会修改物理以太网 MTU。

## 状态文件与权限

状态目录：

~~~text
C:\ProgramData\CampusIPv6Lab
~~~

安装器会限制该目录权限：

- SYSTEM：完全控制；
- Administrators：完全控制；
- Users：只读/执行。

后台任务以 SYSTEM 运行，因此普通账户不能通过修改配置或脚本改变高权限任务行为。

如果已有状态文件损坏，Helper 会停止，而不是生成一个空状态继续运行，以免丢失修改所有权信息。

## 非目标网络恢复

连续多次检测不到运行时安全门后：

- 恢复本项目管理的热点 MTU；
- 删除本项目创建的节点 /128 路由；
- 恢复本项目记录的 SkipAsSource。

默认阈值为 3 次，轮询 5 秒一次。

恢复失败的项目继续保留在状态文件中，不会因为一次恢复失败而丢掉记录。

## 旧版本冲突保护

如果检测到旧任务：

~~~text
CampusIPv6AutoFix
~~~

通用安装器会拒绝继续，防止两个后台任务同时修改网络。

已有稳定配置无需直接覆盖；迁移应单独处理。

## 当前审计状态

已完成：

- Windows PowerShell 5.1 语法解析；
- PowerShell 7 语法解析；
- IPv6 CIDR 匹配与 /64 派生测试；
- 覆写脚本语法与 Fail-Closed 功能测试；

- 无删除默认路由；

- 卸载仅依据本项目记录恢复；
- 诊断脚本不读取订阅、密码、Token、Cookie 或浏览器数据；
- SYSTEM 任务目录已增加 ACL 约束。
