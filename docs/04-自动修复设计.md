# 04 自动修复设计

个人环境中的 AutoFix v6.1 已经长期验证。仓库 v0.2.0 开始提供第一版通用化实现，但仍按“测试版”管理。

## 通用版文件

~~~text
scripts/
├─ Install.ps1
├─ CampusNetworkHelper.ps1
├─ Check.ps1
├─ Uninstall.ps1
├─ Collect-Diagnostics.ps1
├─ Run-Install.cmd
├─ Run-Check.cmd
├─ Run-Uninstall.cmd
└─ Run-Diagnostics.cmd
~~~

## 安全门

通用版不会学习“当前随便一个网络”作为校园网。

默认要求同时满足：

- 物理网卡处于 Up；
- 该物理网卡存在 IPv6 默认路由；
- 默认网关为 link-local IPv6；
- 该接口存在 `2001:da8:a012:` 开头的校园 IPv6 地址。

不能确认时直接 Fail-Closed，不修改系统。

默认校园前缀仅用于当前学校的实验环境；如果以后网络规划变化，应先审计，再改参数。

## 自动发现

运行时动态发现：

- 物理 IPv6 默认路由；
- 实际物理网卡 ifIndex / GUID；
- 当前 IPv6 网关；
- 当前 DHCPv6 / Router Advertisement 地址；
- CrushCloud 核心进程；
- 符合节点 IPv6 前缀的核心 TCP 连接；
- Windows 移动热点接口。

不会写死某位用户的 ifIndex 或 DHCPv6 主机地址。

## IPv6 源地址策略

当前实验基线：

~~~text
RouterAdvertisement -> SkipAsSource=True
DHCPv6              -> SkipAsSource=False
~~~

Helper 在修改前记录原值，离开校园网络或卸载时只恢复自己记录过的地址。

## 节点 /128 绕行

Helper 只观察 CrushCloud 核心进程，并且只处理配置中 `NodeIPv6PrefixText` 指定的节点 IPv6 范围。

当前默认：

~~~text
2406:da18:
~~~

发现实际核心连接后，为对应远端地址添加 `/128` ActiveStore 物理路由。

不会把所有 IPv6 连接都当作代理节点。

## 热点 MTU

仅当：

~~~text
校园强特征成立
AND CrushCloud Core 正在运行
AND 192.168.137.1 热点存在
~~~

才管理热点接口 MTU。

默认目标值：

~~~text
1400
~~~

修改前记录接口 GUID 和原始 MTU。Core 退出、离开校园环境或卸载时恢复原值。

不会修改物理以太网 MTU。

## 非校园网络恢复

连续多次检测不到校园强特征后：

- 恢复本项目管理的热点 MTU；
- 删除本项目创建的节点 /128 路由；
- 恢复本项目记录的 SkipAsSource。

默认阈值为 3 次，轮询 5 秒一次。

## 旧版本冲突保护

如果检测到旧任务：

~~~text
CampusIPv6AutoFix
~~~

通用安装器会拒绝继续，防止两个任务同时修改网络。

参考机继续使用已经验证的个人稳定版；迁移流程单独处理。

## 当前审计状态

已完成：

- 无硬编码 ifIndex=5；
- 无硬编码个人 DHCPv6 地址；
- 无 Windows 网络重置；
- 无禁用 IPv6；
- 无删除默认路由；
- 无修改物理网卡 MTU；
- 卸载只依赖本项目状态文件恢复；
- 诊断脚本不读取订阅、密码、Token、浏览器数据。

尚未完成：

- 第二台独立电脑端到端验证；
- 不同宿舍/不同物理网卡的实机兼容性验证；
- 第三方订阅未来改节点 IPv6 地址范围后的兼容验证。

因此 v0.2.0 仍为测试版。
