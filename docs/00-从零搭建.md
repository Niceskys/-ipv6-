# 00 从零搭建：Windows + Android

> 仅供学习、研究和参考。
> 本页面向电脑和手机都还没有安装相关客户端的干净环境。

## 1. 本项目明确使用哪些客户端

当前验证链路：

~~~text
Windows 电脑
  └─ CrushCloud（Windows 版）
       └─ 校园有线网络 IPv6
            └─ 香港 V6 节点

Android 手机
  └─ NekoBox for Android
       └─ 连接 Windows 移动热点
            └─ SOCKS5 -> 电脑热点地址:7890
                 └─ CrushCloud
~~~

请明确区分：

- 电脑：安装 CrushCloud Windows 版。
- 手机：安装 NekoBox for Android。
- 本项目不使用 NekoBox 电脑版作为电脑端主客户端。
- 本项目手机端不使用 CrushCloud Android 版完成当前热点链路。

如果以后更换客户端，需要重新验证，不能默认配置兼容。

## 2. 当前基线版本

首次独立环境实验优先复现已经验证过的版本，不建议一开始追最新版本。

### Windows 电脑

~~~text
软件：CrushCloud
平台：Windows x64
参考/已验证版本：v2.4.2
~~~

当前项目的覆写、Core 识别和 Helper 测试均以已验证的 Windows v2.4.2 环境为主要参考。

### Android 手机

~~~text
软件：NekoBox for Android
项目：MatsuriDayo/NekoBoxForAndroid
参考版本：1.4.2
现代 ARM64 手机：arm64-v8a APK
~~~

NekoBox 1.4.2 使用 sing-box 1.12.19-neko-1。

如果设备不是 ARM64，不要猜架构，应在 Releases 页面选择实际 CPU ABI 对应 APK。

## 3. 下载来源

### 下载前核验门

首次从零搭建时，AI 必须在真正下载前再次核验：

1. 下载页面仍属于本页列出的项目/服务方；
2. 平台正确：电脑是 Windows，手机是 Android；
3. 实际下载版本与本页基线是否一致；
4. 如果有官方 SHA-256/digest，下载后核对；
5. CrushCloud 若只能取得更新版本，先记录版本并 HOLD 到兼容性核对完成；
6. 不使用论坛转存、网盘搬运、搜索广告或不明镜像替代当前来源。

本页最后核验日期：**2026-10-02**。

## 5. Windows：从干净环境开始

### 5.1 基础网络

先阅读 01-环境检查.md，确认校园有线网络本身可以正常使用，IPv6 未被禁用。

### 5.2 安装 CrushCloud

1. 从上面的 CrushCloud 入口获取 Windows 版。
2. 首次实验优先 v2.4.2。
3. 安装或解压后启动。
4. 登录自己的账户。
5. 使用自己的订阅。
6. 先不要应用本仓库覆写。
7. 先确认普通连接、节点列表和 UI 正常。

不要把账户、订阅 URL、节点 password 或 Token 提交仓库或发给 AI。

### 5.3 核对 Windows 基线

当前已验证环境的关键特征：

~~~text
CrushCloud UI：v2.4.2
mixed-port：7890
允许局域网连接：手机热点需要时必须可用
Core：crushcloudCore.exe
兼容识别：路径限定的 FlClashCore.exe
~~~

如果新版本与这些特征明显不同，先停止并重新审计。

### 5.4 应用 IPv6 覆写

继续阅读：

- 02-客户端配置.md
- 03-IPv6覆写.md

使用：

~~~text
overrides/campus-ipv6.js
~~~

应用后重新启动 CrushCloud Core，再检查目标节点范围。

### 5.5 手机链路前先核对 7890

如果后续需要手机接入，电脑端在启动 CrushCloud 后先检查：

~~~powershell
Get-NetTCPConnection -LocalPort 7890 -ErrorAction SilentlyContinue |
  Format-Table LocalAddress,LocalPort,State,OwningProcess -AutoSize

Get-NetUDPEndpoint -LocalPort 7890 -ErrorAction SilentlyContinue |
  Format-Table LocalAddress,LocalPort,OwningProcess -AutoSize
~~~

当前实验基线要求：

~~~text
mixed-port：7890
allow-lan：开启
~~~

如果 7890 只监听 127.0.0.1，手机不能通过热点访问它。不要直接改防火墙；先核对 CrushCloud 的“允许局域网连接 / allow-lan”设置。

### 5.6 安装 Helper

覆写检查通过后：

~~~text
scripts/Run-Diagnostics.cmd
scripts/Run-Install.cmd
scripts/Run-Check.cmd
~~~

具体按 10-首次独立环境验证清单.md 执行。

## 6. Windows 移动热点

电脑端全部通过后再开启移动热点。

Windows 11 常规入口：

~~~text
设置
→ 网络和 Internet
→ 移动热点
~~~

建议选择：

~~~text
共享我的 Internet 连接：当前校园有线/以太网上行
通过以下方式共享：Wi‑Fi
网络频段：5 GHz（设备支持时）
~~~

然后再打开移动热点。

当前建议：

~~~text
频段：5 GHz
热点电脑 IPv4：通常 192.168.137.1，但必须实际检测
热点 MTU：当前实验基线 1400
物理以太网 MTU：不要修改
~~~

检查：

~~~powershell
Get-NetIPAddress -AddressFamily IPv4 |
  Where-Object {$_.IPAddress -like "192.168.137.*"}

netsh interface ipv4 show subinterfaces
~~~

不要假定热点接口一定叫 WLAN 2，也不要写死它的 ifIndex。

## 7. Android：从干净环境开始

### 7.1 安装正确的软件

手机安装 NekoBox for Android 1.4.2。

现代 ARM64 Android 手机安装：

~~~text
NekoBox-1.4.2-arm64-v8a.apk
~~~

这里的 NekoBox 是手机端，不是 Windows 电脑版。

### 7.2 手机连接电脑热点

先让手机连接 Windows 移动热点。

手机 Wi-Fi 的手动代理保持：

~~~text
关闭 / 无
~~~

NekoBox 自己负责 VPN/TUN 和 SOCKS5。

### 7.3 建立 SOCKS5 配置

在 NekoBox 1.4.2 中新建一个手动 SOCKS/SOCKS5 配置。不同语言界面文字可能略有差异，但不要导入不相关的机场订阅来代替这一条本地 SOCKS 配置。

填写：

~~~text
服务器：电脑实际热点地址
常见值：192.168.137.1
端口：7890
用户名：留空
密码：留空
~~~

服务器地址必须以 Windows 实际检测结果为准。

保存后先不要急着改其他高级选项。

### 7.4 当前 NekoBox 实验基线

~~~text
工作模式：VPN
TUN Stack：gVisor
TUN MTU：9000

FakeDNS：开启
UDP over TCP：关闭

远程 DNS：
https://dns.alidns.com/dns-query

直连 DNS：
https://dns.alidns.com/dns-query

获取唤醒锁：开启
网络变化时重置出站连接：开启/保持默认启用
设备从睡眠唤醒时重置出站连接：开启

SOCKS 自定义出站：
{"network":"tcp"}
~~~

不要关闭 FakeDNS 作为默认方案。
不要打开 UDP over TCP 作为默认方案。

### 7.5 启动顺序

建议每次启动链路按：

~~~text
校园有线网络正常
↓
CrushCloud 启动并选中目标 V6
↓
Windows 移动热点开启
↓
手机连接该热点
↓
NekoBox 连接本地 SOCKS 配置
~~~

手机 Wi‑Fi 本身不要再设置手动代理。

### 7.6 手机验证

先测试：

- 普通网页；
- 小图片；
- 短时间视频；
- 熄屏/唤醒后的首个请求。

不要一开始就用大文件判断整个配置。

如果手机热点本地 ping 稳定，但 SOCKS 出口延迟突然连续升高或超时，应优先检查 CrushCloud 节点或上游，而不是继续盲改手机 MTU。

## 8. AI 从零搭建时的状态识别

AI 读取仓库后，必须先判断当前属于哪种状态：

~~~text
A. 电脑和手机都未安装
B. 电脑已有 CrushCloud，手机未配置
C. 电脑已配置，手机只需接入
D. 已安装但需要检查/修复
~~~

如果是 A，必须从本页开始，不能直接跳到 Helper 安装。

AI 应给出具体操作并根据返回输出继续，不应要求使用者自己判断复杂网络字段。

## 9. “电脑 + 手机从零完成”的判定

只有以下链路全部完成，才能称为从零搭建完成：

~~~text
Windows 校园网络 PASS
↓
CrushCloud Windows PASS
↓
目标 V6 覆写 PASS
↓
Helper / Check / 离网恢复 PASS
↓
Windows 5GHz 热点 PASS
↓
NekoBox Android PASS
↓
手机 SOCKS5 -> 电脑热点地址:7890 PASS
↓
手机 VPN/TUN/DNS PASS
↓
低负载实际访问 PASS
~~~

手机模块如果明确不需要，可以标记“未部署”，不能写成 PASS。

## 10. 版本变化原则

本页记录的是当前已验证基线，不意味着永远只能用这些版本。

如果未来 CrushCloud、NekoBox、Mihomo/sing-box、节点命名或端口发生变化，应先验证差异，再更新仓库。

首次实验不要在中途自动升级客户端。
