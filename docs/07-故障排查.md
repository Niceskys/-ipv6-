# 07 故障排查

原则：先定位哪一层坏，再修改哪一层。

## A. 客户端无节点 / 订阅失败

先确认普通网络是否正常，不要立即修改 IPv6、DNS、路由。

## B. CrushCloud 能打开但无法联网

~~~powershell
Get-Process crushcloudCore -ErrorAction SilentlyContinue
Get-NetRoute -AddressFamily IPv6 -DestinationPrefix "::/0"
Get-NetIPAddress -AddressFamily IPv6
~~~

## C. 手机能连接热点但刷视频卡

~~~powershell
Get-NetNeighbor -AddressFamily IPv4 | Where-Object {$_.IPAddress -like "192.168.137.*"}
~~~

再持续 ping 手机。若本地 ping 稳定，而应用仍卡，问题通常不在 Wi-Fi 射频链路。

## D. 检查 SOCKS 7890

~~~powershell
Get-NetTCPConnection -LocalPort 7890 -ErrorAction SilentlyContinue | Format-Table LocalAddress,LocalPort,RemoteAddress,RemotePort,State
Get-NetUDPEndpoint -LocalPort 7890 -ErrorAction SilentlyContinue | Format-Table LocalAddress,LocalPort
~~~

## E. 检查代理出口长尾

~~~powershell
1..20 | ForEach-Object { $r = curl.exe -x socks5h://127.0.0.1:7890 --connect-timeout 3 --max-time 6 -o NUL -s -w "code=%{http_code} connect=%{time_connect}s start=%{time_starttransfer}s total=%{time_total}s" https://www.baidu.com/favicon.ico; "$_  $r"; Start-Sleep -Milliseconds 500 }
~~~

如果正常时约几百毫秒、故障时突然连续数秒甚至超时，应优先检查节点或上游线路，不要继续盲改手机 MTU。

## 禁止的“排障捷径”

不要因为一次失败就：

- 网络重置
- 禁用 IPv6
- 删除全部路由
- 删除所有虚拟网卡
- 随机改 DNS
- 修改物理网卡 MTU
- 同时开启两个 TUN 客户端
